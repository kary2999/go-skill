# 规范检测说明（v1.7.46+）

> 团队规范的"云端同步"是怎么工作的？后台多久检测一次？覆盖后要不要重启？这篇说清楚。

---

## 1. 一句话总览

**App 后台每小时拉一次远端规范仓的最新 commit SHA，与本地上次同步的 SHA 对比。不同就静默自动拉取、覆盖本地 `references/` 目录的规范文档。无需重启 Claude Code / Cursor。**

---

## 2. 检测的是什么仓库

- **默认仓库**：`https://github.com/kary2999/standards.git`
- **默认分支**：`main`
- **配置位置**：`~/Library/Application Support/TeamStandards/standards-sync.json`
- **想换镜像**：App 内 → `⚡ 安装` → `更新与同步` → `☁️ 规范云端同步` → `⚙️ 配置`

---

## 3. 检测节奏

| 时机 | 行为 |
|---|---|
| App 启动时 | 立即跑一次 |
| 之后 | 每 **1 小时** 跑一次（`time.Ticker`，App 退出即停） |
| 手动触发 | App 里点「立即检查」/「立即同步」按钮 |

**只在 App 运行时跑**。App 没启动 = 不检测。

---

## 4. 检测流程

```
每小时一次：
  1. GET 远端 commits API（带可配置代理）
       └── 失败 → 写 last_check_error，本轮结束
  2. 拿到远端 latest_sha
  3. 比对本地 last_synced_sha
       ├── 相同 → 啥也不干
       └── 不同 → 进入「静默自动覆盖」流程
  4. 下载仓库 zip
  5. 解压、过滤出 .md / .png
  6. 写到本地两个目录（见下）
  7. 更新 last_synced_sha + last_synced_at
```

整个过程**不弹窗、不打断**。失败也只是把错误信息记在配置文件里（前端「规范同步」面板可查），不会弹错误框。

---

## 5. 覆盖的本地路径

```
~/.claude/skills/go-team-standards/references/
~/.cursor/skills-cursor/go-team-standards/references/
```

**只覆盖 `references/` 目录下的 `.md` 和 `.png`**。
- 不动 `SKILL.md` 本身
- 不动其他 skill
- 不动用户其他配置

---

## 6. 覆盖后要不要重启 Claude Code / Cursor？

**不需要。** ✅

原因：
- `references/` 下的文档是 **skill 触发后按需读取**，不是常驻内存
- 下次你提一个会触发 `go-team-standards` skill 的问题（写 Go 代码 / 改 .go / 提到 Kafka/Redis/PG 等关键词），Claude / Cursor 会读到最新版规范

**特例**：如果某次更新动到了 `SKILL.md` 本身（修改 skill 的触发词或描述），那需要重启对应的客户端才能让 skill 注册表刷新。当前自动同步流程**不动** `SKILL.md`，所以无需重启。

---

## 7. 失败处理

- 网络不通 / 仓库迁移 → 错误信息记到 `last_check_error`，下次 tick 再试
- 解压失败 / 写盘失败 → 同上，**不会破坏已有规范文件**（先写新内容，写失败保留旧的）
- 用户改过本地 `references/` 下的文件 → **会被覆盖**。如果你想本地有改动，改完请发 MR 回主仓，不要本地留长期 diff

---

## 8. 我怎么知道某次同步成功了？

打开 App → `⚡ 安装` → `更新与同步` 面板，可以看到：
- 上次检查时间（`last_checked_at`）
- 上次同步成功时间 + SHA（`last_synced_at` / `last_synced_sha`）
- 上次检查的错误（如有）

App 终端 / Console.app 也会打 log：
```
[standards-sync] auto-pulled abc12345 · 12 files · 3 changed
```

---

## 9. 与 App 自身更新的关系

**两条独立的流水线**：

| | 规范同步 | App 更新 |
|---|---|---|
| 拉的是 | git 仓库的 commit | GitLab Release 的 .dmg |
| 频率 | 1h | 1h |
| 发现新版后 | **静默自动覆盖** | **不主动装**，前端 banner 提示 |
| 失败影响 | 用旧规范继续 | 用旧版 App 继续 |
| 用户要不要点确认 | 不用 | 要点「下载」或「一键升级」|

为什么 App 不静默升级？—— 升级要重启 App，重启是显式动作，必须用户授权。
